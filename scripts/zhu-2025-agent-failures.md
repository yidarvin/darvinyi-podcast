[G] Start from the premise: an LLM agent doing a long task isn't one decision, it's a chain. It recalls something from memory, reflects on where it stands, plans a next move, and acts. The paper's core observation is that when one of those early links is wrong, everything downstream inherits the mistake. They call it error propagation. A misread at step four doesn't announce itself at step four — it shows up twenty steps later as a malformed action or a blown step limit, and by then the visible symptom is nowhere near the actual cause.
[O] Which is such an intuitive idea that I'm surprised it needed a paper. Anyone who's watched an agent transcript has seen this — it fixates on the wrong plan early and just never recovers.
[G] Right, and the authors are upfront that the phenomenon itself isn't new. What they say is missing is the mechanism. Prior failure work, including papers on multi-agent breakdowns and case studies of planning brittleness, stops at naming error types or giving qualitative examples. Nobody had built a systematic way to trace a failure back to its actual root, and nobody had turned that diagnosis into something the agent could act on to recover.
[S] So the gap is specifically the causal step — not "here are the ways agents fail," which plenty of papers already do, but "here is the one step, in this specific trajectory, whose correction would have flipped the outcome."
[G] Exactly that. And it's a genuinely harder question than it sounds, because you're making a counterfactual claim about a single trajectory: if the agent had done something different at step four, would it have succeeded at step twenty-nine? You can't rerun reality. The best you can do is either ask a human to judge it, or approximate it computationally — and which of those two AgentDebug does at inference time is exactly the question from our cold open.
[S] Before we get to what they built, what was already out there that this doesn't replace? Chain-of-thought, tree-of-thought, self-reflection loops — agents already do some version of "notice a problem and try again."
[G] They do, and the paper is explicit about the distinction. Search harder at every step, versus find the one step that actually mattered and fix only that — that's the gap AgentDebug is built to close.
[O] Which I now very much want answered, but let's build up to it properly. What did they actually build to study this?
[G] Three things, built in sequence. They started by reading through more than five hundred failed agent trajectories from three benchmarks by hand, and from that reading distilled a taxonomy of failure modes. Then they turned a curated slice of those trajectories into a human-annotated benchmark. And only then did they build the automated debugger. Let's take them in order, since the debugger only makes sense once you've seen the taxonomy it's built on.
[G] The taxonomy first. They split an agent's decision loop into four cognitive modules — memory, reflection, planning, and action — plus a fifth, non-cognitive bucket called system, for things like a tool crashing or the agent simply running out of steps. Each module gets three or four specific leaf error types, seventeen in total: memory has things like hallucinating a false memory or a plain retrieval failure, planning has constraint ignorance and impossible actions, reflection has causal misattribution — correctly noticing something went wrong but blaming the wrong step — and system covers tool execution errors down to just hitting the model's own token limit. Two levels — five modules, seventeen leaves underneath.
[S] I want to flag something now that I'll come back to later: those five modules aren't derived from some blank-slate reading of failures. They're the agent's own architecture — memory, reflection, planning, action — with a system bucket bolted on for everything else. The taxonomy is guaranteed to fit the agent, by construction, because it was built from the agent's own parts list.
[G] Fair, and the authors don't hide it — they say outright that the modular structure mirrors the agent's own decision process. The upside is real: every error type maps cleanly onto a module the annotators already understand, so labeling is fast and consistent. The cost, which the paper doesn't dwell on, is that an error that doesn't cleanly belong to one module — really about two modules miscommunicating, rather than either one being wrong on its own — has nowhere obvious to land.
[O] Taxonomy in hand. Then what?
[G] Then AgentErrorBench.
