[O] So the paper's move is to fix everything except the two variables you actually care about.
[G] Exactly. Same tasks, same metrics, prompts sized to each model's context window, and then sweep architecture against backbone. The authors name three open questions in the introduction. [S] Walk me through the architectures. I want to know what actually differs between them, because in a lot of these papers the answer is "the prompt."
[G] In this paper the answer is largely the prompt and the control flow, and the authors are upfront about that. There are five solo architectures. Zeroshot, which they call ZS, just prompts the model with descriptions of the available actions and parses out an action. No examples, no intermediate reasoning. ZeroshotThink, or ZST, adds a self-think step before each action, where the model writes a thought into memory first, still under a zero-shot prompt. ReAct keeps that self-think step but switches the prompt to fewshot, so you spend context budget on worked examples of reasoning-then-acting traces.
[O] And the two planning ones.
[G] PlanAct generates a fewshot plan before the agent touches the environment at all, stores it in memory, and retrieves it while acting. PlanReAct is PlanAct with the self-think step layered back on top, so the agent both plans ahead and reasons at each intermediate step. The authors' stated intuition there is that since the plan is generated before the agent has seen anything, self-think is what rescues you when the plan is wrong.
[S] That is five. The sixth is the contribution.
[G] BOLAA is the orchestration scheme. Instead of one model handling every action type, you have a pool of labor agents, each specialized to one type of action, and a controller sitting between the environment and that pool. The controller has an agent-selection layer that picks which labor agent to call, constructs the message to it, takes the response back, and parses it into an executable environment action.
[O] How many labor agents did they actually instantiate?
[G] Two. On WebShop, a search agent that only emits search queries, and a click agent that only emits click actions. That is worth sitting with, because the grand phrase "orchestrating multiple agents" cashes out here as splitting a two-verb action space down the middle.
