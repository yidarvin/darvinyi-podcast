[G] Thank you, glad to be here. And I would say the tension you opened with is the paper's actual thesis, not an accident in the results table. The authors' whole complaint is that a single success rate cannot tell you what an agent got wrong. They then build a benchmark that decomposes it, and the decomposition immediately surfaces rankings that a single number would have hidden.
[O] Let us set the stage. What was broken before this?
[G] Three things, and the authors are explicit about all three. First, tasks were not standardized. BEHAVIOR scores success as reaching a target state, something like not stained of fridge. VirtualHome imposes temporal ordering constraints over actions. Nothing made those two commensurable. Second, the modules were not standardized. SayCan and Code as Policies use the language model to sequence a fixed skill set. LLM plus P has the model produce a formal goal and hands planning to a PDDL planner. Ada has the model write planning domain definitions for a lower level planner. Each one drops the language model into a different socket, with different inputs and different outputs.
[S] So every paper is measuring a different thing and calling all of it embodied decision making.
[G] Precisely. And third, the metrics. Nearly everything reported a final success rate. The one prior attempt the authors credit, LOTA-Bench, does break evaluation down, but in their words it is limited to generating action sequences and does not support analysis of fine grained planning errors.
[O] And a single success rate genuinely cannot distinguish four completely different failures. Did the model misread the goal? Hallucinate an object that is not in the room? Ignore a precondition? Or get the ordering wrong?
[S] Those need four different fixes, too. If your agent is failing because it misparses clean the refrigerator, more planning compute buys you nothing.
[O] So how do they unify it, Julian?
[G] Representation first. A state is a pair: a universe of objects, and a set of relational Boolean features. Things like is open of cabinet one, or is on of rag zero and window three. Actions are just a name plus arguments. Then the key move. Goals, subgoals and action sequences are all written as linear temporal logic formulas. The fragment they use is deliberately restricted: an ordered sequence of actions connected by then, ending in a conjunction of propositions that must hold in the final state.
[S] Why is that the key move rather than a notational preference?
[G] Because that one formalism covers both simulators. A BEHAVIOR state goal is the degenerate case with no action prefix. A VirtualHome temporally extended goal uses the prefix. You no longer have two incompatible notions of success. You have one language with two shapes.
[O] And on top of that sit the four modules.
[G] Four, each with a fixed signature. Goal interpretation maps an initial state and a natural language instruction to a logic goal. Subgoal decomposition maps an initial state and a goal to a sequence of logic subgoals. Action sequencing maps an initial state, a goal and a transition model to a primitive action trajectory. And transition modeling maps an operator name to its preconditions and effects, in PDDL.
[S] Here is my real question. If you run all four with a language model, you are back to an end to end pipeline and you still cannot attribute blame. What stops that?
[G] That is the isolation protocol, and I think it is the best engineering in the paper. When they grade action sequencing, goal interpretation and the transition model are supplied as ground truth. When they grade subgoal decomposition, a breadth first search stands in for action sequencing. When they grade transition modeling, an external PDDL planner stands in for action sequencing. Exactly one component is the language model. Everything else is correct by construction.
[O] So a module score is genuinely about that module.
[G] Yes. And each module gets metrics matched to it. Goal interpretation is an F one set matching score against the ground truth logic goal. Action sequencing and subgoal decomposition get execution success rate, meaning does the trajectory run without violating a precondition, and task success rate, meaning does the final state satisfy the goal. Transition modeling gets a logic form F one against expert annotated preconditions and effects, plus planner success rate, where you hand the model's predicted operator definitions to a PDDL planner and see whether it still finds a working plan.
[S] What did they have to build to make this actually run?
[G] Quite a lot, and I think it is underrated. On VirtualHome they newly annotated twenty six task names covering three hundred thirty eight instructions and trajectories, eight hundred one goals, and thirty three transition models with ninety nine preconditions and fifty seven effects. Average trajectory length there is eight point seven six steps, two thousand nine hundred sixty steps in total. BEHAVIOR had no action transition layer at all, so they wrote a symbolic simulator with thirty executable actions, then annotated one hundred task names and trajectories, six hundred seventy three goals, and thirty transition models. Average trajectory on BEHAVIOR is fourteen point six steps.
[O] BEHAVIOR being nearly twice as long per task is going to matter later, I suspect.
[G] It does. One more wrinkle. BEHAVIOR goals use quantifiers, for all and for pairs, which ground out into many valid assignments of atomic propositions. Each task has on average six point seven grounded goals, and roughly four thousand one hundred sixty four goal options. The scorer takes the best matching grounding, which is the only defensible choice, but it does make scoring slightly lenient.

[G] The authors give a mechanistic story with receipts. Failures concentrate on actions with tool mediated preconditions. On BEHAVIOR, for GPT-4o, the open action has a perfect one point zero zero execution success rate, because its preconditions are trivial and stated.
