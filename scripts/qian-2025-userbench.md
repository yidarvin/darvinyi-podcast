[O] What does the agent actually see when it searches?
[G] Each aspect has its own mock search tool over a pre-generated option pool. The base composition per aspect is one best option, three correct options total, ten wrong options, and five noise options. Correct means it satisfies every preference. Best means it also has the lowest total cost, because the budget-aware variant is switched on for all the reported runs. Wrong means it violates at least one preference. Noise means it is absurd — the paper's own example is a flight quoted at a million dollars for a thousand-hour direct trip. Combine several aspects and a single scenario can carry, quote, up to over one hundred options.
[S] And the search tool is unforgiving.
[G] It only returns results when the arguments exactly match the scenario's ground truth. There is also a corrupted-search variant switched on, which fails a search periodically on purpose.
[O] Walk me through a turn.
[G] Episodes are capped at twenty turns. Every turn the agent must make exactly one tool call, and it is one of three: search the database, action which means talk to the user, or answer which means submit option identifiers for scoring. When the agent talks, its utterance is classified by a judge into one of four types — a concrete ask about a preference the user actually holds, a concrete ask about one she does not hold, a vague general question, or ordinary conversation.
[S] And only the first type earns anything.
[G] Only the first type triggers a reveal, and even then the reveal is implicit — the user states the preference sideways, in character. Here is the mechanism that matters for my three-quantities warning. If the agent goes three consecutive turns without a valid concrete ask, the environment gives up on it and proactively reveals one remaining preference on its own.
